# 6. Tour screenshots are captured by a script, from the mock Kite client only

**Status:** accepted (2026-09-26)

The public "How this site works" page shows phone screenshots of every step of the flow. Screenshots taken by hand drift from the real UI, and any taken against a real Kite login could leak holdings and cash into a public page and the git history.

**Decision:**
- The steps live in one manifest, `lib/tour/screens.json`, which both the page and the capture script read.
- `npm run screenshots` runs `scripts/capture-screens.mjs`, a dependency-free script. It drives headless Chrome over the DevTools protocol, with no Playwright or Puppeteer.
  - It captures a 390×844 phone viewport at 2× scale, in light and dark, with reduced motion emulated.
  - It writes WebP files to `public/tour/`, which are committed.
- The script **refuses to run unless the server uses the mock Kite client**. It checks that `/api/kite/login` redirects to our own callback with a mock request token, not to Zerodha. Screenshots therefore only ever show sample data.
- A test fails if any manifest step lacks its light or dark image.

**Consequences:** screenshots are regenerated by hand after UI changes, not in CI, since CI has no running app or Chrome. The images add about 1 MB to the repo.
